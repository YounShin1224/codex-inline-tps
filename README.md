# Codex 输入框 TPS

在输入框底部左侧权限按钮与右侧模型控件之间的空白区域居中、紧凑显示，与模型选择器位于同一水平线；位置随两侧按钮的实际宽度自动调整：

```text
200tok/s·均值200·缓存90.50%
```

当前 TPS 轻微加重，其他信息使用原生次要文字颜色；圆点分隔，数字等宽，单位只显示一次。模型名、请求次数和计算说明放在悬停提示中。

生成期间，第一项根据本对话同模型最近五次有效响应估算；数值前不加额外符号，悬停说明会明确标注估算状态。工具执行或最新响应计时不足时，保留本对话同模型最近一次有效读数。

输入框或模型控件加载中、位置尚未稳定、TPS / 均值 / 本轮缓存率缺少任一有效读数时，整行隐藏，不显示 `—` 占位。数据与位置都就绪后再显示；切换聊天、模型或新一轮缓存数据尚未返回时同样适用。

已经显示的读数不会因打字、光标移动、悬停其他任务或正常尺寸调整而隐藏；有效布局变化会直接同步位置。

## 启动和停止

### macOS

需要 **Node.js 24 或更新版本**和已安装的 Codex 桌面版。双击 **启动 Codex TPS.command**，或在终端执行：

```sh
npm run start:mac
```

启动器按应用标识 `com.openai.codex` 查找当前运行的应用、`/Applications`、`~/Applications` 和 Spotlight，兼容 `Codex.app`、新版的 `ChatGPT.app` 以及重命名的安装。它不会把普通 ChatGPT 应用误认为 Codex。应用装在其他位置时可明确指定：

```sh
node launch.mjs start --app '/path/to/Codex.app'
```

也可设置 `CODEX_TPS_APP`。会话目录继续遵循 `CODEX_HOME`，默认 `~/.codex`。

**如果 Codex 正在运行，助手会等待你保存工作后用 `Cmd+Q` 正常退出，然后自动重新打开并接入。** 关闭窗口不等于退出应用。不会强制结束当前任务。重复启动会复用助手；停止后如果带调试端口的 Codex 仍在运行，再次启动可重新接入。

双击 **停止 Codex TPS.command**，或运行 `npm run stop`，移除状态行并退出助手，Codex 保持打开。运行 `npm run status` 或 `node launch.mjs diagnostics` 查看状态。若要同时关闭调试端口，停止后正常退出 Codex，再从原来的应用入口打开。

`.command` 会查找 PATH、Homebrew 和 `~/.local/bin` 下的 Node.js。若 Node.js 由 nvm、fnm 等工具管理，请在已激活 Node.js 24+ 的终端执行 `npm run start:mac`。下载方式丢失可执行权限时，在本目录执行 `chmod +x *.command`。

助手以独立后台进程运行，不注册登录项或 LaunchAgent，不修改应用包、签名、模型提供商或代理设置。macOS 使用权限为 `0700` 的短临时目录保存 Unix 控制 socket，避免长仓库路径触发系统限制；控制密钥和诊断仍在 `.runtime/`。删除前先停止助手，再删除本文件夹。

### Windows

双击 **启动 Codex TPS.vbs**。如果 Codex 已经打开，辅助程序等待你通过系统托盘正常退出 Codex，然后自动重新打开。不要只关窗口；应用可能仍在托盘运行。

启动入口通过 Windows 本地进程服务独立启动辅助程序，使它不会随调用它的 Codex 执行环境退出。此操作不创建计划任务或开机启动项。

以后通过这个启动入口打开 Codex。字体、主题和字号继承当前 Codex 的界面设置。状态行属于页面内容，不是桌面悬浮窗，点击其他应用不会单独隐藏它。

双击 **停止 Codex TPS.vbs**，移除状态行并退出辅助程序，Codex 保持打开。再次启动可以恢复。若要彻底移除，先停止，再删除本文件夹；之后从原来的 Codex 入口正常启动。

首次接入使用仅监听 `127.0.0.1` 的本地 Electron 调试连接。没有修改 Codex 安装包或注册开机启动；正常启动入口不会带这个组件的调试参数。应用升级后，启动脚本会重新查找当前安装位置。

调试接口具备查看和操控当前渲染页面的能力，请只在可信的本机环境使用。停止辅助程序后，若要关闭该接口，请退出 Codex，再通过原来的 Codex 入口打开。详见 [隐私与安全说明](SECURITY.md)。

## 读数口径

- 第一项：最近一个有效模型响应的输出吞吐量。分子是 Codex 记录的官方输出 token，包含隐藏思考；分母是该响应已完成的 Reasoning / AgentMessage 输出时间区间的合并长度。
- 均值：本对话、同模型的有效输出 token 总数除以有效输出时间总和。估算值不计入，切换模型分别统计。
- cache：当前主会话整轮的加权缓存命中率，即这一轮所有已完成模型请求的缓存输入 token 总和 ÷ 输入 token 总和。一轮从发出一条用户消息开始，包含工具调用后的多次模型续推理；生成中累计，完成后保留结果，新一轮重新计数。主会话当前日志之外的子 Agent 用量不计入。
- 只有缓存百分比保留两位小数，TPS 和均值仍显示整数；部分命中若会被四舍五入成 `100.00%`，显示 `<100.00%`。只有上报的缓存输入总量与输入总量完全相等才显示 `100.00%`。这是输入 token 的复用比例，不是命中缓存的请求数量比例。
- 完整模型计时会排除工具执行时间；重复响应按响应 ID 去重。计时不足一秒、没有可用的模型/响应计时、重复记录冲突或无法可靠对应响应时不生成速度读数。

旧桌面版或 CLI 会话有官方输出用量，却没有模型生成起始时间时，改用请求开始（或上一批工具返回）到输出完成/用量回报的响应时长，数值前不加额外符号，悬停说明会标注计时口径。这个口径可能包含排队、首 token 等待和用量回报延迟，属于响应平均速度估算；不会和有完整模型计时的样本混合计算均值。有完整计时样本时优先使用原口径。没有官方用量的旧导入聊天仍不显示测速。

这些是本地记录推算出的速度，不是服务器精确瞬时 TPS。持久化日志没有逐 token 的实时计数，因此生成中的数值是历史样本预测，不会伪装成实测。没有有效计时的响应不会清空已有有效读数，悬停可查看最近有效样本时间和计时口径。支持包含 `token_usage_record` 的 JSONL、Zstandard (`.jsonl.zst`) 和 gzip 日志；压缩文件在内存中流式读取，不写回对话文件。旧会话恢复后，会自动优先跟踪新建的未压缩日志。不支持的日志不会用字符数冒充官方 token。

悬停状态行可查看计算说明。聊天身份无法确认、模型选择无法匹配或找不到输入框时，会清空或隐藏状态行，避免显示其他聊天的数据。

## 文件和依赖

需要已有 Node.js 24 或更新版本；本机启动脚本自动从 PATH 查找。无第三方运行时依赖，不需要 API Key。

- `main.mjs`：启动、调试连接、按窗口绑定、只读跟踪会话文件。
- `platform.mjs`：macOS 应用身份校验、进程定位、跨平台控制端点和启动锁。
- `launch.mjs`、`*.command`：macOS 独立后台启动和停止入口。
- `metrics.mjs`：token、计时区间、模型归属和均值计算。
- `renderer.js`：继承原生样式的内嵌状态行。
- `cdp.mjs`：本地调试协议连接与隔离环境。
- `.runtime/`：本组件的状态和诊断，不保存对话正文或输入框内容。

如需查看运行状态，可在此目录打开 PowerShell，执行 `node main.mjs status`；`node main.mjs diagnostics` 还会返回字体和居中误差等只读信息。

这是依赖 Codex 内部界面标记的实验性工具，不是官方扩展。仓库提供解析、macOS 启动/控制逻辑和独立浏览器的组件检查；真实 Codex 多窗口行为和应用升级后的兼容性仍需使用者验证。运行检查可使用 `npm test`，浏览器检查会自动寻找 macOS 的 Chrome/Edge、Windows 的 Chrome/Edge 或 Linux 的 Chromium，也可用 `CODEX_TPS_TEST_BROWSER` 指定浏览器可执行文件。测试使用独立临时浏览器配置，不操作现有浏览器或 Codex 窗口。
